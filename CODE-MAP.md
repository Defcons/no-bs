## App shell / tabs / PiP (2026-07-13)
- **All four tab panels stay mounted** (App.tsx `.tabpanel` divs, `hidden` toggled) — Today MUST stay mounted so its workout/PiP/HR/geofence effects keep running when you're on another tab. Each panel is its own scroll container; `go(tab)` saves scrollTop, a `useLayoutEffect` restores it → per-tab scroll memory.
- **PiP auto-enter**: Android **12+ (S)** uses `PictureInPictureParams.setAutoEnterEnabled` — set in `PipPlugin.setAutoEnter` — so the SYSTEM floats the timer on Home, the **Recents/task-view button AND the swipe-up gesture**. `MainActivity.onUserLeaveHint` is the **pre-12 fallback only** (it early-returns on S+); it fires for Home ONLY, which is why task-view never floated the PiP before 1.46.0. Don't run both (double-enter).
- **PiP overlay is portaled to `document.body`** (Today `createPortal`) so it covers whatever tab is showing. `onPipChange`/`setPipAutoEnter` live in Today (always mounted) so PiP arms from any tab. `exitPip()` (native, expands out of PiP) is called on AUTO-end so a stale PiP window doesn't linger.
- **Auto-end duration** = up to `draft.lastActivityAt` (last set edited / break started), not wall-clock. `finishNow(auto, reason?)`: manual=false (wall-clock, alerts on error), watchdog=true (geofence→`"left"` / HR-dropout→`"hr"` → lastActivityAt, silent, exitPip). Never mix them up — onClick handlers must call `finishNow(false)` (a bare `finishNow` ref passes the event as `auto`). On a successful auto save `finishNow` fires `showAutoEndNotification(reason,id,moodIncomplete)` — captures `moodIncomplete` from the draft BEFORE `finish()` clears it. (Geofence no longer shows its own "saved" reminder — this supersedes it.)
- **Header tool sheets + auto-end mood logging** (Phase 3-ish, 2026-07-14): the active-workout header (`.wb-right`) has `.tool-btn` icon buttons — stopwatch + mood (mood gets `.set` accent when both moods logged) — opening `.hr-modal` sheets (`sheet` state); this REPLACED the old `.tools-toggle`/`showTools` collapsible + the inline "Feeling before"/bottom "Feeling after" sliders. `MoodSlider` extracted to its own component (shared by the mood sheet, finish-prompt, and `MoodLogModal`). Auto-end notification carries `extra.logMood=<workoutId>`; `onNotificationTap` (notify.ts — pure-JS `LocalNotifications.addListener("localNotificationActionPerformed")`, **OTA-safe, no APK**, best-effort on cold start) → App `moodLogId` → `MoodLogModal` patches `db.workouts.update(id,{moodBefore,moodAfter})` (local-only, no re-sync). Finish-prompt (`finishAsk`) for unrated mood was already present and stays.
- **Hardware buttons** (`hwButtons.ts` + `HwButtonsPlugin.java`): **the BREAK is started only by a Bluetooth EARBUD volume rocker; the PHONE's own volume buttons stay normal VOLUME** (user decision 2026-07-24, on-device confirmed — the earbud path works). Earbud rockers send AVRCP absolute-volume (NOT key events), invisible to `onKeyDown`/the accessibility service, but with absolute volume (Android default) they move the media level; a `ContentObserver` on `Settings.System` volume (armed via `setCapture`) catches that change, fires `volumeKey` (→ start break / skip a running one via `hwBreakRef`), and snaps the level back. Phone volume KEYS must NOT trigger the break: `MainActivity.onKeyDown` (foreground) and `VolumeKeyAccessibilityService` (locked, extended flavor) never consume them — they call `HwButtonsPlugin.suppressVolumeChange()` so the observer ignores that one level change (`suppressVolumeObserver`, volatile; shared `clearSuppress`/`doSuppress`, 400ms). Net: phone = volume, earbud = break. **Only works with absolute volume ON; locked-screen phone-key suppression needs the extended accessibility service** (standard flavor: a locked phone-key press would still fire a break — minor edge). Headset media button via MediaSession = best-effort (loses to a music app holding the button).
- **EARBUD BREAK — on-device findings 2026-07-30 (S25+/One UI, extended build, `adb logcat -s HwBreak:D`, Spotify playing).** TWO hypotheses REJECTED by the log: (a) key-event false-suppression — the earbud is **pure AVRCP**, zero `onKeyDown`/`onKeyEvent` for earbud presses; only the PHONE button emits a key event (`code=25`, device `pmic_resin`, `external=false`) which the a11y service correctly suppresses (that part works perfectly). (b) "screen-off kills it" — a clean **on-battery, stay-awake-off, screen-OFF** test had the observer firing **repeatedly while locked** (`now=5 last=6 → EARBUD BREAK fire`, many times). So the break **DOES fire in all states — foreground, backgrounded-behind-Spotify, AND locked/screen-off** (same PID throughout; not frozen). **The only real symptom left is intermittent MISSES:** some presses log `onChange now==last (no music-level change)` → nothing to catch. Root of the misses = the **snap-back-to-baseline fights the earbud's own absolute-volume state machine**, so a press occasionally nets zero STREAM_MUSIC movement. Most presses fire; a minority are lost → the "sometimes doesn't trigger" feel. Music-PAUSED was also tested (2026-07-30) and **works too** — the rocker still moves STREAM_MUSIC with Spotify paused, so the observer fires. **NET: the feature works in all tested states with this build; only the occasional miss remains.** LIKELY why "locked" works reliably now = the **`VolumeKeyAccessibilityService` was ON** (keeps the process uncached/unfrozen when the screen is off); if a fresh APK install leaves that a11y toggle OFF, the locked case is the first thing that would regress — check it first. Candidate polish (not yet done, low priority): reduce snap-back-vs-earbud fights / debounce to kill the residual misses. No native fix committed — behaviour is acceptable as-is.
- **Audio ducking** (`HwButtonsPlugin.duck` + `duckAudio()` in hwButtons.ts): break sounds/countdown are Web Audio on STREAM_MUSIC — same channel as Spotify, so they mix in and get buried. `duckAudio(ms)` requests transient `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` so the music app DIMS (not pauses) for the sound, then releases (Handler-delayed; re-arming extends the hold). Called from `playCountdownTick`/`playBreakStart`/`playBreakSound`/`playBuffer` in sounds.ts. No-op on web/old APKs.
- **Break sounds** = `lib/sounds.ts` (all Web Audio synth: `tone`/`strike` for beeps/bell/etc. + a `drum()` engine — pitch-dropping membrane body + filtered-noise attack — for the "War drums / Power kick / Drum roll" patterns). `playBreakSound(id)` for built-ins, `playBuffer`/`decodeSound` for uploads, `playBreakStart()` = the short chirp on `startRest`. Settings **Preview** + RestTimer both handle built-in ids and `custom:<id>`. **Keep-screen-on** = setting `keepScreenOn` (default off) → native `setKeepAwake` window flag (holds in PiP) + web WakeLock. **Reminders** use a dedicated HIGH channel (`reminders`) or scheduled closed-app nudges silently drop.
- **Custom break sounds**: Dexie `customSounds` table (schema **v2**, additive — `db.version(2).stores({customSounds:"++id"})`; blobs stored on-device). Setting `breakSound` = a built-in id OR `custom:<dbId>`; RestTimer pre-decodes the chosen custom clip. Settings picker: file input (audio/*, <5MB, validated via decodeAudioData) + delete. Users supply their own files (copyright-safe).

## Data flow
`ensureBootstrapped()` (in `db.ts`) runs once: seeds the 3-day split into `templates` and imports the bundled sheet snapshot (`src/data/history-seed.json`) via `parseWorkbook`. Guarded by a module-level promise + a `bootstrapped` setting (React StrictMode double-mounts effects → would double-seed otherwise). Future-dated sessions (sheet year typos) are dropped on import.

## Invariants / gotchas
- **`Code.gs` `metaKind` must match the label sets in `sheet.ts`** (NOTE/MOOD/TIME/HR/SKIP). A label the parser treats as meta but the script doesn't → the script writes a duplicate meta row.
- **Geofence and GPS tracker watchers must stay mutually exclusive** — geofence only runs for non-custom sessions, the tracker only for `custom + trackGps`. Both are foreground-service geolocation watchers; running two at once double-drains battery. Each `start*` guards a stop-before-`addWatcher`-resolves race (a `starting` flag) to avoid leaking a watcher.
- **Exercises/sets carry a `uid()` `id`** used as the React key — never key those lists by array index (local `showNote` state would bleed across a reorder/remove).
- **PiP is rendered as an OVERLAY** (`{pipMode && <PipView/>}` on top), not by unmounting the workout UI — so returning from the background doesn't reset per-card state (note toggles). A stale overlay is cleared on foreground via a native `isInPip()` check. Aspect ratio is set from JS (`setPipAutoEnter(enabled,w,h)` → `PipPlugin.autoW/autoH` → `MainActivity.onUserLeaveHint`).
- **Mid-session alternative exercise** (2026-07-29): a normal (template) session can add an ad-hoc exercise (e.g. bench unavailable → curls). `addExercise` flags it `added` on `ExercisePerf` when `!draft.custom`; `ExerciseCard` gets `editableName`/`onRemove` per-exercise (`draft.custom || ex.added`) so the template's own rows stay fixed while added ones are named/removable. `finish()` keeps an added exercise only if it has a name. NOTE: added exercises save to local History but do NOT sync to the Google Sheet — `Code.gs doPost` only writes to EXISTING block rows (it never inserts a new exercise row into a template block); only fully-custom Alternative sessions get an auto-created block.
- **Time of day** (2026-07-29): app sessions already store a full ISO timestamp in `date`; `format.clockTime` surfaces local `HH:MM` in History (blank for bare-date sheet imports). `sheetSync` sends `timeOfDay` (local `HH:MM`) → `Code.gs` writes a **"Time of day"** meta row (added to `metaKind`, `metas`, `createBlock`, `metaRow`); `sheet.ts` `SKIP_LABELS` recognises it so import never treats it as a fake exercise. Requires the user to REDEPLOY `Code.gs`.
- **History "Edit" loads the workout into the Today editor** (`beginEdit` sets `draft.editId`); finishing UPDATES that row (no re-sync — would append a sheet column). Not the old modal.
- Per-exercise +/- step: `stepForExercise(name, fallback, override)` resolves **override → name-heuristic (single-arm "1h"/incline → 2 kg) → Settings default**. The override is an optional `step` on the template exercise (`DayTemplate.exercises[].step`) AND on `ExercisePerf` — set via the TemplateEditor "±kg" field, carried into the session by `buildExercises`, and preserved in the xlsx/JSON `_data` backup (not written to the visible sheet). `buildExercises` seeds set weights from the heaviest N when last session had more than the scheme's sets.
- **Only mark a workout `synced` when the sheet took the exercises** (`syncWorkout` checks `result.written`), so a name mismatch (`ok:true, written:[]`) doesn't silently claim success.
- **Service worker is web-only.** `main.tsx` registers the vite-plugin-pwa SW **only in the browser**; on the native app it *unregisters* any SW + clears caches. A precaching SW on native serves a stale bundle after a Capgo OTA (version badge bumps, UI doesn't) — the classic Capgo-vs-SW trap. `vite.config.ts` sets `injectRegister: null` so registration is manual. Never re-enable auto-registration.
- The sheet is transposed: dates across columns, exercises as rows under a day-block header; each block has its OWN date columns. Two historical layouts (2018-19 two-col label vs 2021+ combined). Parser detects the date row and reads exercise values at those column indices.
- `finish()` saves exercises with any set weight OR a note; prefilled (untouched) weights DO get saved by design (prefill = intended lifts).
- HR only works over HTTPS (or localhost). For real phone use, deploy behind HTTPS (homelab NPM + Tailscale). Pair straps THROUGH the app, not OS Bluetooth.

- `src/lib/workbook.ts` + `src/lib/download.ts` — **`.xlsx` backup/restore** (SheetJS, lazy-loaded). `exportXlsx`/`workbookTabs` build the transposed year tabs + Bodyweight tab (mirrors the Google-Sheet layout) **plus a hidden `_data` tab of lossless JSON** (incl. GPS tracks); `importXlsx` prefers `_data`, else parses visible tabs via `sheet.ts`; `applyBackup` adds missing workouts (dedup day@@date) + merges bodyweight. `download.ts` `saveFile` = web download / native share-sheet (`@capacitor/filesystem`+`share`). Wired in Settings (Backup). See `docs/ROADMAP.md` for the commercialization plan (local-first, optional cloud, "No BS").
